## 运行环境
这个系统的运行环境只有一台机器，配置如下：
1. CPU：ARMv7 4核 32位
2. 内存：1G
3. 操作系统：威联通NAS
4. 使用docker，docker compose

## 架构设计（单机、低资源优先）
1. 数据源：NAS本地文件系统为唯一真相，数据库仅做索引与缓存。
2. 配置来源：所有配置项必须来自配置文件（默认 `config.json`），禁止写入数据库。
3. 服务分层：
   - Web API 层：HyperExpress 提供 REST/JSON 接口 + 静态资源服务。
   - 任务执行层：后台任务队列（数据库表 + 轮询 worker），避免引入 Redis 等额外组件。
   - 媒体处理层：调用系统二进制工具（优先 ffmpeg/ffprobe、exiftool/metadata 工具），降低 Node 端内存占用。
4. 存储设计：
   - SQLite（单文件）存储：文件索引、缩略图索引、人像特征、回忆视频索引、任务队列。
   - 配置文件存储：用户列表、角色/权限、扫描计划、缩略图参数等全部配置项。
   - 缩略图缓存目录：按内容 hash/尺寸分层存储，支持按需生成与定时清理。
5. 前端架构：
   - 纯 HTML/CSS/JS，模块化组织（ESM），无重型框架。
   - 时间轴/无限滚动 + 虚拟列表，避免一次性渲染大量图片。
6. 安全与权限：
   - 角色 + 文件夹 ACL，服务端强制校验，前端仅作展示控制。
7. 性能原则：
   - “以时间换空间”：避免大缓存、避免内存常驻大数组，尽量流式处理。
   - 后台任务限速/限并发，夜间执行高开销任务。

## 开发顺序（从可用到完整）
1. 基础设施：配置读取与校验、目录扫描、SQLite 索引、基础 API。
2. 图库浏览：缩略图生成、时间轴分页/滚动、EXIF 解析与排序。
3. 权限系统：用户登录、角色/文件夹 ACL、生效策略（配置文件驱动）。
4. 文件管理：上传/删除/移动/重命名，权限校验与索引同步。
5. PWA：离线缓存、静态资源预缓存、最近内容缓存。
6. 人像系统：人脸检测、向量存储、聚类与命名管理。
7. 回忆系统：规则生成、视频合成、列表与播放。
8. 优化与运维：任务调度、缓存清理、日志与告警。

## 业务细节与技术方案（关键点）
1. 配置管理
   - 规则：全部配置项必须来源配置文件；变更需重启或触发热加载。
   - 方案：启动时加载 `config.json` 并做 schema 校验；支持 SIGHUP/接口触发重新加载（可选）。
2. 文件索引
   - 规则：按配置的根目录扫描；忽略隐藏/系统目录；支持增量扫描。
   - 方案：数据库记录 path、mtime、size、hash(可选)；扫描时优先对比 mtime/size。
3. 时间轴排序
   - 规则：EXIF 时间优先，其次视频元数据时间，再次文件 mtime。
   - 方案：解析失败时回落；统一时区处理；保存标准化时间戳到索引。
4. 缩略图
   - 规则：支持多尺寸；按需生成 + 后台批量生成；可配置时间窗口。
   - 方案：优先调用 ffmpeg/图像工具；生成结果缓存到磁盘 + 索引表。
5. 大图查看
   - 规则：前端按需加载；支持原图与适配屏幕尺寸的中图。
   - 方案：服务端按参数返回原图/中图；中图可按需生成。
6. 权限与角色
   - 规则：角色（管理员/编辑/访客）；文件夹 ACL 继承；默认拒绝。
   - 方案：所有 API 统一权限中间件；用户与 ACL 从配置文件加载。
7. 文件管理
   - 规则：上传/移动/删除后同步索引；回收站可选（软删除）。
   - 方案：文件操作成功后写任务队列更新索引与缩略图。
8. 人像系统
   - 规则：仅对图片做人脸检测；允许手动合并/拆分人物。
   - 方案：低并发批处理；向量存储 + 简单聚类（增量 DBSCAN/层次聚类）；命名写入人物表。
9. 回忆系统
   - 规则：按时间/地点/人物生成主题；模仿苹果相册的“年度/月份/节日/人物”规则。
   - 方案：规则引擎 + ffmpeg 合成；封面帧缓存；定时任务生成。
10. PWA 离线
   - 规则：静态资源离线；最近访问缩略图/列表缓存。
   - 方案：Service Worker + Cache API；离线只读。
11. 稳定性
   - 规则：低内存环境运行；任务失败可重试。
   - 方案：统一错误日志、指数退避重试、任务超时与断点续跑。

## 技术栈
因为运行机器的性能配置过低，所以所有代码均要求以**最省资源的形式**去编写，严格遵循**以时间换空间的概念**，具体技术要求如下：
1. 运行时：Node.js 22
2. 编写语言：TypeScript（strict）
3. Web 框架：HyperExpress
4. 前端：纯 HTML + CSS + JS
5. 数据库：SQLite（单机轻量，仅存索引与任务）
6. 配置文件：JSON（`config.json`）
7. 媒体工具：优先使用系统二进制（ffmpeg/ffprobe、exiftool 或同类）

## 人脸识别技术栈（准确率优先 / 离线单张）
1. 推理框架：ncnn（ARMv7/低内存优先）
2. 人脸检测：SCRFD_10G 或 SCRFD_34G（640px 缩略图输入，准确率优先）
3. 人脸识别：ArcFace ResNet100（准确率优先）
4. 运行策略：单张顺序处理，允许慢但要稳定；非实时
5. 资源降级（内存不足时）：
   - 识别模型降级：ResNet100 -> ResNet50
   - 检测模型降级：SCRFD_34G -> SCRFD_10G -> SCRFD_2.5G

## 回忆生成算法（离线幻灯片）
1. 数据准备（索引阶段提前写入 SQLite）
   - 必备字段：id, path, type(photo/video), takenAt, width, height, duration
   - 轻量质量指标：分辨率过低/过暗/过亮/过糊降分
   - 去重字段：hash/phash（用于近似重复剔除）
   - 可选增强：faceCount, isFavorite, hasGps/locationKey
2. 回忆主题（候选来源）
   - 同日回忆：按 month/day 匹配历史年份（优先）
   - 时间密集事件：相邻拍摄间隔 < 2 小时聚为一个事件
   - 近期回忆：最近 30/90 天作为兜底
6. 推荐挑选数量
   - 单次回忆：20-40 张
   - 视频：最多 2-3 个（可仅用封面帧）
7. 低内存实现要点
   - 生成时分页查询，避免一次性加载全量
   - 仅保留候选 top N（例如 200）
   - 单张顺序处理：评分 -> 去重 -> 分桶 -> 插入 top
   - 只在内存存放必要字段，结果写入 JSON

## 代码要求
1. 所有配置项必须来自配置文件，禁止写入数据库。
2. 配置文件必须做 schema 校验；校验失败直接拒绝启动。
3. 所有列表 API 必须分页；支持游标或时间戳翻页。
4. IO 操作使用流式读写；避免一次性读入大文件。
5. 后台任务限并发，默认 1～2。
6. 所有路径必须规范化并做安全校验（防止路径穿越）。
7. 记录必要日志，避免高频 debug 输出。
8. 数据库操作尽量批处理；避免 N+1 查询。
